# UI-стандарт EXØS (mobile)

Правила, по которым собираются экраны. Если новый экран им не следует — это баг.

## 1. Безопасные зоны (edge-to-edge)

На Android 15+ (One UI 7 и т.д.) и во всех сборках Expo SDK 54 приложение всегда рисуется **под** статус-баром и панелью навигации. Система ничего не сдвигает за нас.

- Каждый полноэкранный экран/оверлей сам отвечает за верхний отступ:
  - обычный экран — корень `SafeAreaView` из `react-native-safe-area-context` с `edges={['top', 'bottom']}`;
  - экран во вкладке — `edges={['top']}` (низ обрабатывает таб-бар), либо `ScreenContainer withTabBar`;
  - контент под статус-баром (обложка артиста) — плавающие кнопки сдвигаются на `useSafeAreaInsets().top`, сверху кладётся тёмный градиент для читаемости статус-бара.
- **Никогда** не хардкодить высоту статус-бара/навигации (`top: 12`, `paddingBottom: 34`). Только `insets`.
- Шторки (`AnimatedModal variant="sheet"`) сами добавляют `insets.bottom` — не дублировать.
- `Modal` рисуется edge-to-edge (`statusBarTranslucent`, `navigationBarTranslucent`) — это уже в `AnimatedModal`.

## 2. Шапка экрана

Всегда `ScreenHeader` (`components/ui/ScreenHeader.tsx`):

| Как экран появился | `leading` | Иконка |
| --- | --- | --- |
| выезжает справа (push) | `back` | `chevron-left` |
| выезжает снизу (present) | `close` | `chevron-down` |

- Высота строки — `LAYOUT.headerHeight` (52), кнопки — `HeaderIconButton` (40 px, зона нажатия ≥ 44).
- Боковые слоты всегда зарезервированы, заголовок по центру.
- Отдельные круглые кнопки (в т.ч. поверх картинок) — `HeaderIconButton` (`tone="overlay"` для фото). В стеклянном режиме он сам становится стеклянным.

## 3. Отступы и размеры

- Горизонтальный отступ страницы — `LAYOUT.gutter` (16).
- Шкала отступов — `SPACING` (`constants/spacing.ts`), без произвольных чисел.
- Минимальная зона нажатия — 44 (`LAYOUT.minTouch`); для мелких иконок — `hitSlop={touchSlop(size)}`.

## 4. Текст

- Только `AppText` (кап масштаба шрифта `LAYOUT.maxFontScale = 1.3` уже внутри).
- У `TextInput` — `maxFontSizeMultiplier={LAYOUT.maxFontScale}`.
- Никакого текста строкой в разметке: всё через `t('section.key')`.
- Параметры — `t('playlist.deleteMessage', { name })`, словарь с `{name}`.
- Счётчики — `tn('tracks', n)` → «1 трек / 3 трека / 5 треков»; формы `_one/_few/_many` в секции `count`.

## 5. Клавиатура

- `KeyboardAvoidingView behavior="padding"` на **обеих** платформах (на edge-to-edge Android окно больше не ужимается само).
- Скроллы с полями — `keyboardShouldPersistTaps="handled"`.

## 6. Анимации

- Стеклянный режим: переходы из `components/glass/transitions.ts`, пружины из `GLASS_SPRING` (`constants/glass.ts`). Появление ≈ 180 мс, закрытие ≈ 200 мс с `ease-out`.
- Не вводить новые длительности/пружины вне этих констант.

## Чек-лист перед мержем экрана

- [ ] Проверен на устройстве с жестами **и** с кнопочной навигацией.
- [ ] Ничего не залезает под статус-бар / вырез камеры.
- [ ] Шапка через `ScreenHeader`, стрелка соответствует направлению появления.
- [ ] Нет захардкоженного текста, счётчики через `tn`.
- [ ] Работает при крупном системном шрифте.
- [ ] Клавиатура не перекрывает поля.
